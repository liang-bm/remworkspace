# RemWorkspace

[中文](README.md) | [English](README.en.md) | 日本語

RemWorkspace は、チャット、デスクトップのレム、日記、毎日のタスク、集中タイマーをまとめた、ローカルで使うデスクトップのワークスペースです。メイン画面で話したり、レムについてくる小さな吹き出しに入力したりできます。休憩には農場や五目並べも遊べます。

リポジトリ名は `remworkspace` です。アプリの画面と実行ファイルは引き続き RemChat、Python パッケージは `remcompanion` という名前です。以下のボタン名、起動コマンド、ファイルの場所は、現在のアプリの名前に合わせています。

Windows と Linux x86_64 に対応しています。表示言語は設定から簡体字中国語、繁体字中国語、English、日本語を選べます。一部の新しい画面には中国語のボタンが残っているため、この説明にも実際のボタン名を載せています。

普段使う場合は [Releases](https://github.com/liang-bm/remworkspace/releases) から OS に合ったパッケージをダウンロードしてください。レムのアニメーションは同梱されています。Python や音声モデルを先に入れなくても、画面を開き、日記、タスク、集中タイマー、農場を使えます。チャットには自分のモデルサービスを設定します。音声は初期状態でオフです。

ソースのリポジトリには個人の記録、API キー、声の重み、モデル実行環境を含みません。[ソースから起動する](#ソースから起動する)場合は、Release のアニメーション素材パックをプロジェクト直下に解凍できます。

## 初めて起動するとき

実行に必要なファイルがそろったパッケージを持っている場合、Windows では `desktop-app/RemChat.exe` を開きます。Linux ではインストール後のアプリメニューから RemChat を選ぶか、パッケージ内の `desktop-app/RemChat` を実行します。

1. レムだけが見えているときは、レムを右クリックして「显示 / 隐藏主聊天窗口」を選び、チャット画面を表示します。
2. 左側の「設定（设置）」から「一般（通用）」を開き、「表示言語（界面语言）」を選びます。
3. 「モデルと API（模型与 API）」でチャットモデルを設定します。オンライン API なら Base URL、API キー、モデル ID を入力し、「保存并启用」で保存して有効にします。入力欄の下でも、そのモデルが選ばれていることを確認してください。
4. すでに動いているローカルの互換サービスにも接続できます。ローカルモデルをインストールする場合は「本地 Qwen」を選び、「安装本地模型」を押して画面の案内に従います。モデルには追加のディスク容量とメモリが必要です。
5. チャット画面に戻り、Enter で送信します。Shift + Enter は改行です。上部の「播放」は最初はオフで、初めてオンにすると音声の準備画面が開きます。文字だけのチャットには必要ありません。

API 設定を保存しただけでは通信しません。「测试连接」や「获取模型」を押すとリクエストが送られ、サービスによっては料金が発生します。コーディング向けプランの API には利用条件があり、通常のチャットには使えない場合があります。

## チャット、モデル、記憶

長い返信はメイン画面で、短い入力は小さな吹き出しで使うと便利です。どちらも同じ会話を共有します。上部の「悬浮窗」で吹き出しを表示、非表示にできます。

メッセージには Markdown の見出し、リスト、引用、表、コードブロックを表示できます。コードだけをコピーしたり、Markdown の例をソースとプレビューで切り替えたりできます。長い返信は展開でき、過去の会話を読んでいる間に勝手に最下部へ戻りません。右クリックで元の Markdown もコピーできます。コードや HTML は実行しません。

入力欄の「＋」は今回の送信に添付するファイルを選びます。「选择工作空间」は関連するフォルダーの指定です。選んだだけで全ファイルを調べたり、書き換えたりはしません。送信前に添付内容を確認してください。添付一覧から外しても元のファイルは残ります。Ask / Plan などのモードで使える操作は画面に表示されており、任意のコマンドを実行する権限を与えるものではありません。

一つの提供元に複数のモデルを保存できます。モデル ID はサービスが受け付ける名前を指定し、コンテキストや出力上限が不明なら空欄にします。上部の中文 / 日本語は読み上げ言語です。表示言語を変えても、保存済みの会話や声の設定は変わりません。チャットの返信は初期設定では中国語です。

覚えてほしい好みを伝えたら、「記憶の管理」で保存された内容を確認してください。編集、削除、インポート、エクスポートもできます。いつも守ってほしい好みは「会話と人格」の長期指示に直接書けます。会話、記憶、日記は別々に保存しています。

## デスクトップのレムと外観

レムの右クリックメニューからメイン画面を開き、待機動作を選び、アプリを終了できます。レムは待機したり、うたた寝したり、自分でゆっくり歩いたりします。眠っている間はマウスを近づけても跳びません。軽くクリックすると起きる動作を再生し、ドラッグした場合はドラッグとして扱います。会話や集中をしている間は、その動作を優先します。

「設定 > 外観と動き」でテーマ、壁紙、壁紙の薄さ、レムの大きさを調整できます。背景管理では自分の画像を取り込み、起動時や日付に合わせて切り替えられます。Ctrl + / Ctrl - はメインチャットの文字サイズだけを変えます。

「アニメーション工房」は自分のフレーム画像を取り込み、プレビューして管理する場所です。RemChat のレムは画像フレームを使って動きます。取り込むときは画面に書かれた画像と動作情報の形式に合わせてください。

## マイク入力と読み上げ

「設定 > 语音输入」で音声認識を有効にします。音声を文字にする ASR と、返信の読み上げは別の設定です。

- メインチャットと吹き出し：マイクを押すと録音し、音量の波形を表示します。一時停止、再開、停止して文字起こし、キャンセルを選べます。結果は下書きに入るので、確認してから送信します。
- 日記編集画面：「语音记录」を押すと録音用のタイマー画面が開きます。停止して文字起こしすると、現在の日記に挿入します。

会話や日記を切り替えると、録音はキャンセルされます。遅れて届いた結果が別の記録に入ることはありません。録音や認識に失敗しても元の下書きは残します。録音の一時ファイルは処理後に削除し、日記の添付には自動保存しません。

オンライン認識では接続先とモデルを指定します。設定例は SiliconFlow の `https://api.siliconflow.cn/v1/audio/transcriptions` と `TeleAI/TeleSpeechASR` です。ASR 専用キーを保存するか、保存済みの提供元キーを使えます。録音を止めて文字起こしすると音声がそのサービスへ送られ、料金が発生する場合があります。認識できる言語はモデルによって異なります。

ローカル認識は Whisper.cpp の `whisper-cli` と対応モデル、または自分で起動した互換サービスを選びます。ASR モデルを自動でダウンロードすることはありません。ローカルサービスの接続先は、例えば `http://127.0.0.1:8080/v1/audio/transcriptions` のようなループバックアドレスです。

Windows では既定のマイクへのアクセスを許可してください。Linux では `pw-record`、`parec`、`arecord` のいずれかを用意し、デスクトップのセッションから起動します。

### レムの読み上げを使う

チャット上部の「播放」か、吹き出しの ♪ を押すと音声の準備画面が開きます。両方の画面で同じスイッチを使います。今は使わない場合、そのまま文字のチャットを続けられます。

1. FFmpeg と C/C++ コンパイラーを用意します。Windows では [FFmpeg の公式ページ](https://ffmpeg.org/download.html) から Windows 版を入手し、解凍した `bin` をアプリのインストール先の `engines/ffmpeg/bin` に置きます。同梱 DLL とライセンスも残してください。[Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) の C++ ワークロードも必要です。Ubuntu / Debian では `sudo apt install ffmpeg build-essential` を実行します。音声依存の二つの部品をコンパイルするためです。アプリは sudo やシステムツールのインストールを自動実行しません。
2. CPU または NVIDIA GPU を選び、「環境をインストール」を押します。迷ったら CPU を選んでください。GPU には CUDA 12.8 対応ドライバーが必要です。固定版の GPT-SoVITS、独立した Python 環境、基礎モデルをダウンロードし、ファイルと依存を確認します。初回は数 GB の空き容量と時間を用意してください。進捗画面を閉じても実行中のインストールは続き、音声はオフのままです。
3. 「Google Drive の資料を開く」か、[声のダウンロードフォルダー](https://drive.google.com/drive/folders/1RvbxWWKFjzlHd4PHGXQU9_3EExOs4DgM) を開きます。`rem-voice-inference-v2pro.voice-parts.json` と `rem-voice-inference-v2pro.zip.001`、`.002`、`.003` の全てを、名前を変えずに同じフォルダーへ保存します。手動で解凍しないでください。
4. 「推論パックを読み込む」で `.voice-parts.json` を選びます。アプリが分割ファイルを照合・結合し、学習済みの重み、参照音声、書き起こしを取り込み、この端末のアカウントの鍵で暗号化します。準備が整ったら「音声を有効にする」を押します。以後は「播放」か ♪ で切り替えます。

推論パックは約 256 MiB です。このパックを使った CPU での中国語・日本語の音声合成を確認しています。元の学習データは含まれず、読み上げのための再学習も不要です。新しい端末での環境構築は、システムツール、ネット接続、ドライバーによって成否が変わります。失敗した場合は詳細が表示され、文字のチャットには影響しません。

取り込み時の論理パスは `models/tts/rem/gpt/rem-gpt.ckpt`、`models/tts/rem/sovits/rem-sovits.pth`、`voice-source/reference.wav`、`voice-source/reference.txt` です。取り込み後はリソース保管庫で保存され、元のダウンロードファイルは自動削除されません。基礎エンジンは `engines/GPT-SoVITS`、独立した音声環境は `runtime/gpt-sovits` に置かれます。別アカウントの暗号化ファイルをコピーせず、各端末でパックを読み込んでください。

中文 / 日本語で読み上げ言語を選びます。チャット API とローカルの声は別の設定です。音声を使わない場合はずっとオフのままで構いません。

## 集中タイマーと予定日

メインチャット上部の予定日表示をクリックすると編集できます。予定名と `YYYY-MM-DD` 形式の日付を入力し、複数の予定を保存できます。「展示」で表示する予定を選びます。指定しなければ、近い予定を優先して表示します。当日や過ぎた日付も表示できます。

上部の「集中」で時間を決め、「開始」を押します。チャットの壁紙がデスクトップ最前面の幕になり、暗いオーバーレイと動く残り時間を表示します。レムは見えるままで、吹き出しだけ一時的に隠します。終了後は元の表示設定に戻ります。

幕の上で一時停止や再開ができます。「集中を終了」または Esc でいつでも終了できます。時間になるとデスクトップへ戻り、休憩を知らせます。複数の画面でも同じタイマーを使います。システムの壁紙やショートカットは変更せず、画面ロックにもなりません。

Linux では最前面表示と複数画面の範囲が X11 / XWayland やウィンドウマネージャーに左右されます。ネイティブ Wayland では制限される場合があります。

## 日記と毎日のタスク

「功能广场 > 日记」を開くと、日付と時刻で並ぶタイムラインが見られます。カレンダーで日付を選び、「今天」で今日に戻ります。「写一刻」で新しい記録を作り、「阅读 / 编辑」で既存の記録を開きます。「返回总览页面」でタイムラインへ戻れます。

ツールバーで太字、マーカー、見出し、リスト、引用を付け、カラー絵文字や添付ファイルを入れられます。文字を選ぶと小さなツールバーが出ます。右クリックか Shift + F10 で書式メニューを開きます。Markdown を直接入力しても、同じ編集欄で書式がリアルタイムに表示されます。編集とプレビューを切り替える必要はありません。

「代码块」で言語を選び、コードを入力します。構文ごとに色が付き、「复制」で囲み記号を含めずコード全体をコピーできます。コードは記録するだけで、実行しません。

日付の横でタグを付けます。「搜索日记」は日付をまたいでタイトル、本文、日付、タグを検索し、複数キーワードと一部のあいまい検索に対応しています。結果を押すと実際の記録を開いて該当箇所へ移動します。検索を消すとタイムラインへ戻ります。検索内容は外部へ送信しません。

毎日のタスクは、その日の記録より前に表示されます。同じ日に複数の日記を書いてもチェックリストは一つです。総覧右上の「设置日记模板」で曜日、本文テンプレート、毎回入れるタスクを一行ずつ設定できます。該当する日付を開くと一度だけタスクを作ります。新しい日記にテンプレートを使い、既存の本文は上書きしません。

画像、音声、動画、通常のファイルを添付できます。画像はサムネイルを表示し、音声と動画はクリックしたときにシステムのプレーヤーで開きます。通常のファイルは実行せず、保存フォルダーを開きます。一つの日記に最大 64 件、各ファイルは最大 128 MiB です。添付はローカルに保存し、モデルには自動送信しません。

書く手を止めると自動保存し、「保存」でも保存できます。保存に失敗したときは下書きを残すので、画面の案内を確認してから移動してください。削除した記録はごみ箱に入り、復元できます。「导入 / 导出」で旧テキストや Markdown を取り込めます。`.remjournal` は書式、時刻、タグ、添付も保存する形式です。

## 農場、単語カード、五目並べ

### ピクセル農場

「功能广场 > 像素花园」で農場に入ります。草地をクリックして近づき、矢印キーか WASD で移動します。数字キーの 1 から 4 で耕す、種まき、水やり、収穫を選び、Space または E で使います。種をまいたら水をやり、育ったら収穫してください。

ラディッシュ、ニンジン、ブルーベル、トマト、トウモロコシ、カボチャ、イチゴ、ヒマワリを選べます。現実の時間で成長し、アプリを閉じても進み具合は残ります。左下の井戸か右上の池の桟橋でじょうろを満たせます。入口の門は E で開閉します。木、岩、柵、水は通れず、橋は渡れます。

通常の視点はレムを追い、「全图视角」で全体を見られます。場面のプレビューで季節や昼夜を切り替えられます。小屋はこの版では開いていません。現在の遊び場は屋外の農場です。

### 単語カード

「功能广场 > 单词卡片」でローカル辞書や自分のカードを取り込みます。辞書を選んで意味と例文を読み、「记住了 / 还没记住」で復習を記録します。自分なりの理解は「我的笔记」に書けます。カードとノートはインポート、エクスポートできます。

「AI帮记」を押したときだけ現在のモデルを呼びます。説明や例文はまず画面で確認し、「解释加入笔记」や「添加所选例句」で選んだ内容を保存します。辞書の原文と保存した資料は分けて表示します。

### 五目並べ

「功能广场 > 五子棋」で対局を始めます。新しい盤は 22×22、黒が先手で、五つ並べると勝ちです。待った、ヒント、新しい対局を選べます。

標準の相手はローカルのアルゴリズムです。「让当前聊天模型参与落子（耗 Token）」をオンにしたときだけモデルに手を考えさせます。局面の説明も自分で要求する操作です。通常のローカル対局に API は必要ありません。

## 声かけ、プロジェクトの記録、追跡リング

「功能广场 > 主动陪伴」で通知の間隔と静かにする時間を決めます。自動通知は最初はオフです。「体验一次提醒」で試すこともできます。ここでいう操作していない時間は RemChat 内のものです。他のアプリのキーボードやマウスを監視しません。返信、読み上げ、集中中は自動通知を待たせます。

「功能广场 > 项目过程」は、ローカルのツールが残した会話記録を見る場所です。ツール、日付、メインの会話を選び、公開ユーザー入力、段階の情報、トークンの使用状況を読みます。対応するツールは一覧の表示に従ってください。「暂不支持」は未対応です。「跟随最新」で新しい記録を追い、過去の会話を選ぶと追従を止めます。

「接入与会话管理」で選んだ会話をデスクトップの追跡に追加します。リングは同期状態を表示します。隠したリングはサイドバーの「恢复跟踪环」か「設定 > 一般」から戻せます。観察を止めても、元のツールのタスクは止まりません。目標として表示するのは、ツールが明示したネイティブの目標か公開の `/goal` だけです。

プロジェクトの指示やプロンプト一覧は、読み取れるローカル記録から取得します。指示ファイルはその会話の実際の作業フォルダーにあるものです。編集するとそのプロジェクトに影響します。隠れたシステムプロンプトや内部の推論は表示しません。

## アプリ、MCP、スキル、使用量

「設定 > 接入资源」で、どの接続や操作を有効にするかを選びます。

「应用」のカードは、登録済みの `codex://` リンクから Codex の接続画面やアプリ画面を開きます。ログインと許可はそちらで行います。リンクに対応した Codex のインストールが必要です。RemChat はそのログイントークンをコピー、保存しません。画面が開いても接続済みとは扱わず、アプリの下書きも自動送信しません。

「MCP 服务」は外部ツールの接続設定です。Context7、Playwright、Sequential Thinking、Filesystem、Memory、Fetch、Git、読み取り専用 GitHub のプリセットがあります。選ぶと未保存、無効の下書きが入ります。パス、引数、権限を確認して保存し、明示的に接続してください。選んだだけでソフトをインストールしたり、サーバーを起動したりはしません。

「技能库」はローカルのスキルを管理します。「事件 Hook」と「接入草稿」には自分で設定した操作を保存します。設定を取り込むだけで接続やコマンドは有効になりません。内容を理解して信頼できるサービスを使ってください。

「全部用量」はローカルで取得したトークンのカレンダーと推移を表示します。モデル、日付、指標で絞れます。記録がない日はゼロではなく不明です。記録済みの値と観察した増分は分けて表示し、二重に加算しません。料金は元の記録にある場合だけ表示します。

## 保存場所、バックアップ、プライバシー

会話と記憶は `data/memory.sqlite3`、日記や各活動は `data/plaza/` に保存します。日記をバックアップするときは `data/plaza/diary.sqlite3` と `data/plaza/diary-media/` の両方が必要です。データベースだけでは添付ファイルが足りません。予定日は `data/countdown-days.json` にあります。

会話と日記のデータベース自体は現在暗号化していません。共用パソコンでは自分のアカウントとバックアップを保護してください。リモートのチャット API にはメッセージと、その要求に使う履歴や記憶を送ります。オンライン ASR には録音、ウェブ検索には検索語を送ります。日記と添付を自動でアップロードすることはありません。

API キーは Windows の現在のユーザーの DPAPI、または Linux の Secret Service に保存します。設定のエクスポートにはキーを含めません。接続先のホストを変えると、キーの確認が必要になります。

リソース保管庫は私有の声の素材を AES-256-GCM で保存し、キーをシステムのアカウントで保護します。保護された素材は通常ローカル読み上げだけを許可し、学習と元ファイルの書き出しはオフです。使用中だけ一時的に復号し、通常の終了時に片付けます。素材の権利を与える機能ではなく、使用中のファイルをログイン中のユーザーや管理者から隠すものでもありません。強制終了や停電ではアカウント専用の一時フォルダーが残る場合があります。

保管庫とキーの復元に必要なものは、別のローカルバックアップに残してください。Windows のアカウント変更や Linux のキーリング紛失で、復元できなくなる場合があります。Linux のキーは元のインストール先にも紐付きます。実際の `data/`、設定、モデル、声、保管庫、復元パッケージを公開リポジトリへ入れないでください。

記憶の検索は通常 SQLite + FTS5 を使います。sqlite-vec によるベクトル検索は任意で、実際のローカル Embedding サービスが必要です。最初は無効で、モデルを自動ダウンロードしません。普段の利用にベクトルサービスの準備は必要ありません。

## ソースから起動する

Python 3.12 と Tk を使います。使用権のあるキャラクター素材を先に用意してください。待機画像は `app/remcompanion/assets/pet/idle/idle_*.png`、ほかの動作は `app/remcompanion/assets/pet/actions/` に置きます。既存の保管庫がある場合は次の節で復元できます。公開ソースにはこれらの画像を含めていません。

### Windows

プロジェクトのルートで PowerShell を開き、専用環境を作ります。

```powershell
py -3.12 -m venv runtime\control
.\runtime\control\Scripts\python.exe -m pip install Pillow==12.3.0 Pygments==2.19.2 cryptography==50.0.2 sqlite-vec==0.1.6
if (-not (Test-Path config\rem_companion.toml)) {
    Copy-Item config\defaults\rem_companion.toml config\rem_companion.toml
}
$env:REM_HOME = (Get-Location).Path
$env:PYTHONPATH = Join-Path (Get-Location) 'app'
.\runtime\control\Scripts\python.exe -m remcompanion.desktop
```

既存の設定は残します。次回もこの環境の Python で起動してください。`platforms/windows/从源代码启动.cmd` を使う場合は、先に `runtime\control` を有効にします。

### Linux

グラフィカルなデスクトップのセッションで、プロジェクトのルートから実行します。

```bash
test -f config/rem_companion.toml || cp config/defaults/rem_companion.toml config/rem_companion.toml
bash platforms/linux/scripts/Setup-LinuxDesktop.sh
bash platforms/linux/Start-RemChat.sh
```

このセットアップは専用の Linux フロントエンド環境、Tk、フォントをダウンロードします。システムのソフト、チャットモデル、声の素材はインストールしません。システム側に X11 / XWayland、Xft、fontconfig が必要です。録音ツール、キーリング、モデルの実行環境は別に準備します。Windows の実行環境やアカウントで暗号化したファイルは、Linux にそのまま移せません。

インストールできる Linux パッケージを持っている場合は、解凍して中の `Install.sh` を使います。私有のローカルパッケージには案内に従って `--private-local` を付けます。そのパッケージを公開配布用としてアップロードしないでください。

## ローカル素材の復元と任意のベクトル検索

上の Python 環境と `PYTHONPATH=app` を準備します。次の `python` はその環境の実行ファイルです。Windows では `.\runtime\control\Scripts\python.exe`、Linux では `runtime/desktop-linux-xft/bin/python` に置き換えられます。

```text
python -m remcompanion.private_resource_cli status
python -m remcompanion.private_resource_cli verify
python -m remcompanion.private_resource_cli restore-local --vault-directory "YOUR_PRIVATE_VAULT"
```

`YOUR_PRIVATE_VAULT` はリポジトリの外にある保管庫の実際の絶対パスに置き換えてください。元のアカウントとキーが必要です。`restore-local` はキャラクター素材を復元し、声は保護されたまま必要なときに使います。個人の指示や API 設定も戻すときだけ `--include-configuration` を付けます。自分のローカル環境で行う操作です。

ベクトル検索を使う場合は、先に実際のローカル Embedding サービスを起動し、モデル名とバージョンの識別子を指定します。

```text
python -m remcompanion.private_resource_cli semantic --allow --base-url http://127.0.0.1:8081/v1 --model YOUR_EMBEDDING_MODEL --revision YOUR_MODEL_REVISION
```

この操作は設定を保存するだけで、モデルを起動、ダウンロードしません。重みを変えたらバージョン識別子も変えてください。サービスが使えないときは通常の記憶検索に戻ります。

## 困ったとき

- レムだけが見える：右クリックしてメインチャットを表示します。
- モデルにつながらない：選択したモデル、Base URL、モデル ID、キーを確認します。ローカルならサービスの起動も確認してください。声だけの問題なら「播放」をオフにして文字で使えます。
- マイクに音が入らない：既定の入力機器と権限を確認します。Linux は録音ツールも確認してください。
- 日記を保存できない：下書きを残したまま、画面のエラー、空き容量、アクセス権を確認して再試行します。
- Linux で文字が欠ける、コピーできない：CJK フォントを確認します。WSLg は表示された案内に従って `wl-clipboard` を用意してください。
- 保護された TTS が不明なポートを拒否する：自分で起動したサービスか確認します。不明なローカルサービスを流用しないでください。

問題を報告するときは、OS、操作手順、具体的なエラーを知らせてください。API キー、個人の会話、日記、声のファイル、復元パッケージは添付しないでください。

通常の不具合や機能の提案は [Issues](https://github.com/liang-bm/remworkspace/issues) に投稿できます。中国語、英語、日本語で受け付けます。脆弱性、流出した認証情報、個人データの問題は、[セキュリティの案内](SECURITY.md)に従って非公開で報告してください。コードや説明を修正する場合は[貢献ガイド](CONTRIBUTING.md)を確認してください。
