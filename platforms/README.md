# Operating-system boundaries

- `windows/`: PowerShell/CMD launchers, Windows image utilities, Windows PyInstaller specification, backed-up Windows release script.
- `linux/`: native Bash launch/setup, independent Linux build, archive, install/upgrade/uninstall helpers and release manifest.
- `app/remcompanion/platforms/windows/` and `app/remcompanion/platforms/linux/`: independent native Python implementations. Shared application functionality imports through the platform facade.

Existing root launchers and `scripts/` paths remain thin compatibility entries; their implementation is not duplicated. Native files use the project root two levels above platform launchers and three levels above platform `scripts/`, so models, configuration and caches stay in the existing project, not in the platform directory.

## Windows

`platforms/windows/Start-RemChat.ps1` launches the verified desktop EXE when present; `platforms/windows/从源代码启动.ps1` launches source. `platforms/windows/Start-RemCompanion.ps1` opens the existing training control centre. `platforms/windows/Build-Desktop.ps1` uses the existing desktop-build environment.

`platforms/windows/scripts/Setup-Compiler.ps1` is an explicit, opt-in compiler preparation step. It downloads fixed official Inno Setup 6.7.3, verifies SHA256 and the Authenticode publisher, then uses the official portable mode. The compiler, cache, logs and temporary files stay under the chosen project's Windows tool directories; it does not add PATH, file associations or a compiler uninstall entry. Existing modified/incomplete tools are preserved and rejected, not silently replaced. `-DownloadPython <existing-python.exe>` selects an existing downloader when Windows PowerShell TLS is unavailable. The build itself never installs this compiler automatically.

`platforms/windows/scripts/Deploy-VerifiedDesktop.ps1 -PlanOnly` computes changes without creating backups or modifying the live project. Publishing copies only program/document sources from app/docs/scripts/tests and the two platform directories, then replaces the verified Windows onedir bundle with rollback. It excludes assets, runtime/cache/data/models/background/tmp/dist/build paths, bytecode, temporary `verify_*` scripts and linked source files. User model/configuration/memory/voice/background/pet files are not release sources.

## Linux

`bash platforms/linux/scripts/Setup-LinuxDesktop.sh` prepares the process-local front-end runtime without sudo or system-package changes. `bash platforms/linux/Start-RemChat.sh` opens the source desktop. The original `scripts/Setup-LinuxDesktop.sh` redirects here; platform launchers no longer need root aliases.

`bash platforms/linux/Diagnose-Fonts.sh` explicitly inspects the selected source interpreter's actual per-character font fallback. Starting with Linux0.3.6, `desktop-app/RemChat --diagnose-fonts` runs the same diagnostic inside that exact frozen ELF, without starting the ordinary desktop/models or acquiring its lease. Normal Linux startup still uses the incumbent three-window desktop and shared crash-log helper; Windows startup/spec/source are unchanged. Diagnostics do not modify system fonts, and collection is not pixel acceptance. See [font troubleshooting](../docs/platform/linux-fonts.md).

`bash platforms/linux/scripts/Setup-LinuxBuild.sh` prepares the project-local front-end and pinned build tools (no sudo or models). `bash platforms/linux/Build-Desktop.sh` then writes only `dist/linux` / `build/linux`. The build itself does not install dependencies. `REMCHAT_PYTHON` selects a Linux build interpreter; `REMCHAT_FONT_DIR` selects the verified Noto/OFL build inputs when building a separate source checkout.

The Linux bundle now includes its CJK font and license, and matching project-runtime C++ libraries rather than an incompatible older system library. Generated fontconfig/cache files go into the selected application's `cache/fontconfig-linux`, not the read-only bundle. A real frozen bundle passed 15/15 cold-start/resource/native-close checks on this machine's Ubuntu20.04/WSLg; source and synthetic packaging gates passed 22/22. This is not a claim of universal Linux distribution compatibility, full ARGB or public asset licensing.

## Future GitHub Release inputs

The two `release-manifest.json` files describe separate payloads and remaining release gates. Windows `Build-Setup.ps1 -ReleaseRoot <isolated-payload> -Version <semver> -IsccPath <existing-ISCC.exe>` compiles `RemChat.iss`; no compiler is automatically installed. Linux `Package-Desktop.sh <isolated-payload> <semver> <output-directory>` makes a Linux-only tarball plus checksum and rejects Windows EXE/DLL/PYD files. Normal PyInstaller relative shared-library links are preserved only when they resolve to real files within the same bundle; absolute, escaping, broken and cyclic links are rejected before an output directory is created. Neither entry uploads, commits or publishes anything.

Both entries reject payload roots containing user data/model/runtime/engine/voice/background directories. The payload configuration must be a separately reviewed **public default**, never the existing user's configuration. Windows setup preserves an existing config (`onlyifdoesntexist`) and preserves it during uninstall (`uninsneveruninstall`); models and user-created memory/log/cache files are not installer-owned. Users can choose the install directory, including another drive. Setup uses per-user registration and refuses install/uninstall while the desktop's `Local\RemCompanionUI` mutex is held; it never force-stops an unknown user process.

Windows compilation and a real private desktop install/upgrade/uninstall passed 35/35 checks under an isolated acceptance AppId, including actual SQLite bytes, existing valid TOML, user-file sentinels, three-window cold-start, adjacent configuration and running-app refusal. The generated personal installer has not been installed over the existing project. These checks do not establish pixel-level wizard QA, signing, every Windows version or public redistribution rights. Linux installation/upgrade has its own native implementation and evidence below; it is not a Windows Setup feature.

Public packaging additionally requires `public-release-review.json` inside the isolated payload: `schema: 1`, `config_public: true`, `assets_redistributable: true`, a nonempty `reviewer`, and `config_sha256` matching that exact default TOML. These are review attestations, not automatic license verification. The existing Rem artwork, icon and Japanese voice/trained weights have **not** been granted redistribution rights by adding these scripts: replace them with appropriately licensed assets or obtain authorization before approving the gate. Neither public packager copies existing voice/trained model files.

This mode grants no redistribution rights. It uses its own **RemChat Local Build** installation identity and `local-setup.exe` filename; the wizard warns against public upload. `-VerificationBuild` selects a third, test-only identity; never distribute a verification installer as the normal product. ## Native Linux installation (not deb/rpm/AppImage)

The Linux tarball carries `Install.sh`, `Uninstall.sh`, `installer/` and a complete `release.json` file-fingerprint manifest. Normal-user Python 3.8+ installs the frozen desktop into an explicit dedicated target and creates a per-install XDG `.desktop` entry. No sudo, Windows process, system Python modification or model download is involved. Package code is in `platforms/linux/scripts/`; its native instance implementation is maintained once in `app/remcompanion/platforms/linux/instance.py` and collected only by the Linux bundle.

Upgrade preserves configuration, SQLite memory, backgrounds, models and voice/runtime directories. Unknown or modified incoming program files and modified launchers are refused. Uninstall removes only still-matching owned files; modified files, user data and transaction backups remain. The installer and desktop hold the same Linux-only user lease, so running-app changes are refused without killing processes. Ordinary exceptions roll back; an interrupted transaction is refused on the next install and requires reviewed recovery, not deletion of the installation root.

`Package-Desktop.sh <payload> <version> <output> --private-local` requires a matching private review and produces a `-local` archive and checksum; default public mode still requires the independent redistribution gate. Linux code and artifacts contain no Windows EXE/DLL/PYD/native modules. Shared OS-neutral chat/UI/business code remains a single maintainable source, not two diverging copies. Setup/runtime/build directories and native binaries must never be shared across operating systems.

See [Linux install instructions](../docs/platform/linux-install.md) and [actual lifecycle evidence](../docs/remchat-20261003-linux-install-task-log.md). Verified scope is this Ubuntu20.04/WSLg environment, not all distributions or pixel-level GUI acceptance.
